# Contributing to 30 Days of React TypeScript Challenge

Thank you for your interest in contributing to this project! This document provides guidelines for contributing.

## How to Contribute

### Reporting Issues

If you find any issues, errors, or have suggestions for improvements:

1. Check if the issue already exists in the [Issues](https://github.com/Abilash-K/30-Days-React-Typescript-Redux-Challenge/issues) section
2. If not, create a new issue with:
   - Clear title and description
   - Steps to reproduce (if applicable)
   - Expected vs actual behavior
   - Screenshots (if applicable)

### Suggesting Enhancements

We welcome suggestions for:
- Additional examples
- Improved explanations
- New exercises
- Better code samples
- Updated dependencies

### Pull Requests

1. **Fork the repository**
   ```bash
   git clone https://github.com/Abilash-K/30-Days-React-Typescript-Redux-Challenge.git
   cd 30-Days-React-Typescript-Redux-Challenge
   ```

2. **Create a branch**
   ```bash
   git checkout -b feature/your-feature-name
   ```

3. **Make your changes**
   - Follow the existing code style
   - Add examples in the appropriate day's folder
   - Update README if necessary
   - Test your code

4. **Commit your changes**
   ```bash
   git add .
   git commit -m "Add: description of your changes"
   ```

5. **Push to your fork**
   ```bash
   git push origin feature/your-feature-name
   ```

6. **Create a Pull Request**
   - Provide a clear description of changes
   - Reference any related issues
   - Wait for review

## Code Style Guidelines

### TypeScript
- Use TypeScript for all React components
- Define proper interfaces for props and state
- Avoid `any` type unless absolutely necessary
- Use meaningful variable and function names

### React
- Use functional components with hooks
- Follow React best practices
- Keep components small and focused
- Use proper prop types

### Documentation
- Write clear comments for complex logic
- Update README files when adding new content
- Include examples in code samples
- Explain the "why" not just the "what"

## Content Guidelines

### Adding New Examples

1. Place examples in the appropriate day's `examples/` folder
2. Include comments explaining the code
3. Ensure code is production-quality
4. Test that examples work correctly

### Updating Existing Content

1. Maintain consistency with existing style
2. Don't remove working examples without good reason
3. Update related documentation
4. Ensure backward compatibility

## Community Guidelines

- Be respectful and constructive
- Help others learn
- Share knowledge and experiences
- Follow the [Code of Conduct](CODE_OF_CONDUCT.md)

## Questions?

If you have questions, feel free to:
- Open an issue
- Start a discussion
- Reach out to maintainers

Thank you for contributing to this learning resource! 🙏
